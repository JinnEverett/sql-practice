# P06 · ex07 📏 Giá của isolation level khi tranh chấp

Đo bằng `pgbench` (có sẵn trong container `sql-practice-pg`), 8 client, 4 luồng, 8 giây mỗi lần, `lab`, Postgres 18.6, container dùng chung 4 nhân. **Mỗi ô là 1 lần chạy**, nhiễu cỡ vài chục %; chỉ tin vào chênh lệch lớn.

Script `hot.pgb` (đổi `random(1, 4)` thành `random(1, 1000)` cho trường hợp (b)):
```
\set id random(1, 4)
BEGIN;
SELECT v FROM p06.hot WHERE id = :id;
UPDATE p06.hot SET v = v + 1 WHERE id = :id;
COMMIT;
```
Chạy: `docker exec -e PGOPTIONS="-c default_transaction_isolation=serializable" sql-practice-pg pgbench -U postgres -n -f /tmp/hot.pgb -c 8 -j 4 -T 8 --max-tries=1 lab` (với khoảng trắng trong tên level thì viết `read\ committed`; `--max-tries=100` để retry tự động).

## Số đo thật
| trường hợp | level | tps (chỉ giao dịch thành công) | giao dịch lỗi (`--max-tries=1`) |
|---|---|---|---|
| (a) 4 dòng nóng | READ COMMITTED | **4 614** | 0 |
| | REPEATABLE READ | 3 249 | **40 489 (60.9%)** |
| | SERIALIZABLE | 3 132 | **38 502 (60.6%)** |
| | SERIALIZABLE, retry (`--max-tries=100`) | 3 080 | 0, nhưng **12 740 (51.7%)** giao dịch phải chạy lại; latency TB 2.6 ms (so với 1.7 ms ở READ COMMITTED) |
| (b) 1 000 dòng | READ COMMITTED | 8 394 | 0 |
| | REPEATABLE READ | 8 156 | 375 (0.57%) |
| | SERIALIZABLE | 8 665 | 408 (0.59%) |
| | SERIALIZABLE, retry | 8 566 | 0; 377 (0.55%) chạy lại |

## Giải thích
- **Tranh chấp quyết định tất cả.** Với 1 000 dòng, xác suất hai giao dịch cùng chạm một dòng thấp: RR/SERIALIZABLE gần như miễn phí (0.6% lỗi, tps ngang READ COMMITTED trong phạm vi nhiễu). Với 4 dòng nóng, hơn 60% giao dịch RR/SERIALIZABLE bị hủy vì `could not serialize access due to concurrent update`.
- **READ COMMITTED không lỗi vì nó chờ**: UPDATE gặp dòng bị khóa thì xếp hàng rồi đọc phiên bản mới nhất. RR/SERIALIZABLE thì hủy, vì snapshot cũ không còn hợp lệ. Cùng một công việc, "chờ" cho thông lượng cao hơn khoảng 40% ở mức tranh chấp này (4 614 so với 3 080–3 249 tps) và không cần mã retry. Cái giá là phải tự đảm bảo logic đúng dưới READ COMMITTED (ex04, ex06).
- **Retry không miễn phí**: ở (a) hơn một nửa giao dịch chạy ít nhất 2 lần, tức tải thật gấp ~1.5 lần số giao dịch hữu ích.
- Quy mô lớn hơn: tăng số client hoặc tập trung tải vào ít dòng làm xác suất xung đột tăng nhanh. Thiết kế để giảm tranh chấp (tách bộ đếm, ghi append-only rồi gộp) có lợi hơn chọn level; xem R-tier.
