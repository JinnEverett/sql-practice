# R10 · ex09 📏 Thời gian chạy và thời gian chặn của các thao tác DDL theo quy mô

Bảng `t(id int PK, amount numeric, ref text, created_at)`: 100k / 1M / 5M dòng (7 MB / 71 MB / 356 MB kể cả PK). Mỗi thao tác đo **thời gian chạy** của lệnh DDL và **thời gian chờ** của một `SELECT` và một `INSERT` đến sau khi lệnh đã chạy được 0.15 giây (hai truy vấn "nhìn thấy" lệnh DDL nếu nó còn giữ khóa tại thời điểm đó; lệnh nào xong trước 0.15 giây thì không bị bắt, ghi `–`).

## Số đo thật (Postgres 18.6, Docker, lab; **một lần chạy** mỗi ô, bảng dựng lại cho từng N)

| thao tác | 100k | 1M | 5M | khóa & chặn ai |
|---|---|---|---|---|
| `ADD COLUMN c int NOT NULL DEFAULT 0` (hằng) | 1.9 ms | 1.9 ms | **2.1 ms** | khóa tích tắc; **không đổi theo N** |
| `ADD COLUMN c numeric DEFAULT random()` (volatile) | 140 ms | 1 083 ms (chặn SELECT 923 ms, INSERT 925 ms) | **7 747 ms** (chặn 7 512 / 7 504 ms) | viết lại bảng, ACCESS EXCLUSIVE |
| `ALTER COLUMN id TYPE bigint` | 92 ms | 867 ms (706 / 710 ms) | **8 784 ms** (8 559 / 8 550 ms) | viết lại bảng + dựng lại PK, ACCESS EXCLUSIVE |
| `CREATE INDEX` (thường) trên `amount` | 79 ms | 443 ms (SELECT 0.9 ms, **INSERT 291 ms**) | 3 268 ms (SELECT 1.4 ms, **INSERT 3 117 ms**) | khóa SHARE: **đọc được, ghi bị chặn** |
| `CREATE INDEX CONCURRENTLY` | 90 ms | 603 ms (4.8 / 1.6 ms) | 4 245 ms (1.2 / 2.2 ms) | không chặn đọc/ghi; chậm hơn ~30% |
| `SET NOT NULL` trực tiếp | 8.7 ms | 102 ms | 383 ms (chặn SELECT 234 ms, INSERT 236 ms) | quét bảng dưới ACCESS EXCLUSIVE |
| `ADD CONSTRAINT CHECK … NOT VALID` | 2.0 ms | 1.7 ms | 1.8 ms | khóa tích tắc |
| `VALIDATE CONSTRAINT` | 7.3 ms | 53 ms | 344 ms (**không chặn**: 1.1 / 2.5 ms) | SHARE UPDATE EXCLUSIVE |
| `SET NOT NULL` (sau khi CHECK đã validate) | 1.8 ms | 1.5 ms | **1.4 ms** | bỏ qua bước quét |

Chưa đo ở 10M+ (`shop_l`-cỡ); các dòng tăng tuyến tính ở trên cho phép ngoại suy: viết lại bảng ~1.7 giây / 1M dòng (5M dòng: 8.8 giây). Số đo `SELECT/INSERT chờ` ở 100k không có (thao tác kết thúc trước mốc 0.15 giây).

## Giải thích
- **Có hai loại thao tác.** (1) Chỉ đụng catalog, tức thì và không phụ thuộc N: `ADD COLUMN` với default hằng, `ADD CONSTRAINT … NOT VALID`, `SET NOT NULL` sau khi có CHECK đã validate, `DROP COLUMN`. (2) Phải đọc/ghi lại dữ liệu: `ALTER COLUMN TYPE`, `ADD COLUMN` default volatile, `SET NOT NULL` trực tiếp, `ADD FOREIGN KEY`, `CREATE INDEX`: thời gian ∝ N, và mức chặn do loại khóa quyết định.
- **Loại khóa quyết định ai bị chặn, không phải thời gian.** `CREATE INDEX` thường chạy 3.3 giây ở 5M dòng nhưng SELECT vẫn chạy (1.4 ms); chỉ các lệnh ghi bị chặn 3.1 giây. `ALTER COLUMN TYPE` chạy 8.8 giây và chặn cả đọc lẫn ghi 8.6 giây. `VALIDATE CONSTRAINT` quét 344 ms mà không chặn ai.
- **Chi phí của sự an toàn:** `CREATE INDEX CONCURRENTLY` chậm hơn bản thường ~30% (4.2 giây so với 3.3 giây ở 5M) và cần hai lần quét bảng, đổi lại không chặn ghi. Đường NOT VALID → VALIDATE → SET NOT NULL tổng cộng ≈ 346 ms so với 383 ms của `SET NOT NULL` trực tiếp, nhưng trong 346 ms đó không truy vấn nào bị chặn (so với 234 ms chặn).
- **Quy tắc đo được:** bảng 5M dòng (356 MB) chặn ghi ~3 giây cho `CREATE INDEX` và chặn đọc+ghi ~8.6 giây cho `ALTER COLUMN TYPE`. Ngưỡng "người dùng thấy" cỡ vài trăm ms: vượt qua ngưỡng đó (từ ~1M dòng với thao tác viết lại bảng) phải dùng cách an toàn.
- Giới hạn: một lần chạy mỗi ô trên VM cloud, đĩa ảo; thời gian chặn đo bằng hai truy vấn mẫu chứ không phải tải thật. Một truy vấn chạy lâu đang giữ khóa sẽ làm mọi con số "chờ" tệ hơn nhiều (hàng đợi khóa, ex08).
