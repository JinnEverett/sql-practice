# O06 · ex04 — Dựng một replica bằng Docker

Đã chạy thật với `postgres:18` (18.6). `PGDATA` trong image là `/var/lib/postgresql/18/docker`.

## 1. Mạng và primary
```bash
docker network create o06-net
docker run -d --name o06-primary --network o06-net --shm-size=256m -e POSTGRES_PASSWORD=postgres postgres:18
docker exec o06-primary psql -U postgres -c "CREATE ROLE replicator WITH REPLICATION LOGIN PASSWORD 'repl'"
# cho phép kết nối replication: pg_hba mặc định chỉ có 'host all all all scram-sha-256' mà "all" KHÔNG gồm replication
docker exec o06-primary sh -c 'echo "host replication replicator all scram-sha-256" >> "$PGDATA/pg_hba.conf"'
docker exec o06-primary psql -U postgres -c "select pg_reload_conf()"
```
Mặc định của image đã đủ cho primary: `wal_level = replica`, `max_wal_senders = 10`, `max_replication_slots = 10`, `hot_standby = on`.

## 2. Replica
```bash
docker run -d --name o06-replica --network o06-net --shm-size=256m -e PGPASSWORD=repl postgres:18 \
  bash -c 'gosu postgres pg_basebackup -h o06-primary -U replicator -D "$PGDATA" -R -X stream -C -S replica1 -c fast \
           && exec docker-entrypoint.sh postgres'
```
Ý nghĩa:
- `pg_basebackup`: sao chép cả thư mục dữ liệu của primary khi nó đang chạy (nhất quán nhờ WAL).
- `-R` (`--write-recovery-conf`): tạo `standby.signal` (báo cho Postgres khởi động ở chế độ standby) và ghi `primary_conninfo` (+ `primary_slot_name`) vào `postgresql.auto.conf`. Đã kiểm: `primary_conninfo = 'user=replicator password=repl … host=''o06-primary'' port=5432 …'`.
- `-X stream`: nhận WAL qua một kết nối thứ hai **trong lúc** sao chép, nên bản sao không thiếu WAL nếu primary dọn WAL cũ.
- `-C -S replica1`: tạo **replication slot** `replica1` để primary giữ WAL cho tới khi replica nhận.
- Chạy `pg_basebackup` trước, rồi `exec docker-entrypoint.sh postgres`: entrypoint thấy `PG_VERSION` đã có nên bỏ qua `initdb`.

Log replica khi lên:
```
LOG:  entering standby mode
LOG:  consistent recovery state reached at 0/2000120
LOG:  database system is ready to accept read-only connections
LOG:  started streaming WAL from primary at 0/3000000 on timeline 1
```

## 3. Chứng minh
```sql
-- trên primary
SELECT state, sync_state, sent_lsn, write_lsn, flush_lsn, replay_lsn FROM pg_stat_replication;
--  streaming | async | 0/30A7850 | 0/30A7850 | 0/30A7850 | 0/30A7850
SELECT slot_name, slot_type, active, restart_lsn FROM pg_replication_slots;
--  replica1 | physical | t | 0/3000000
-- trên replica
SELECT pg_is_in_recovery();         -- t
INSERT INTO ryw(v) VALUES ('z');    -- ERROR:  cannot execute INSERT in a read-only transaction
SELECT count(*) FROM ryw;           -- 1000 (dữ liệu 1000 dòng ghi ở primary đã có mặt)
```
Lag lúc rảnh: `write_lag` 0,2 ms · `flush_lag` 2,2 ms · `replay_lag` 2,4 ms · lệch 0 byte.

## 4. Dọn
```bash
docker rm -f -v o06-replica o06-primary
docker network rm o06-net
```

## Điều cần nhớ
- Replica **phải cùng major version** và kiến trúc với primary (sao chép từng byte).
- `max_connections` ở replica ≥ primary.
- Slot giữ WAL: nếu replica chết lâu, primary không dọn WAL và đĩa đầy. Đặt `max_slot_wal_keep_size`.
- Đây là bất đồng bộ (`sync_state = async`): primary chết có thể mất vài giao dịch cuối chưa tới replica.
