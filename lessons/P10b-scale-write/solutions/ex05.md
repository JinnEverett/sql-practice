# P10b · ex05 📏 ALTER TABLE: tức thì hay rewrite

Đo bằng `\timing` trong `BEGIN … ROLLBACK` trên `p10.t_s` (10k), `p10.t_m` (1M), `p10l.t_l` (10M; bảng tổng hợp, **không phải `shop_l`**), Postgres 18.6, 1 lần/ô. Cột "khóa" là mức khóa trên bảng trong suốt thời gian lệnh chạy.

| lệnh | khóa | `t_s` | `t_m` | `t_l` |
|---|---|---|---|---|
| `ADD COLUMN x int` | ACCESS EXCLUSIVE (chớp nhoáng) | 1.5 ms | 0.73 ms | 0.83 ms |
| `ADD COLUMN x int DEFAULT 0` (hằng) | như trên | 1.2 ms | 0.57 ms | 0.76 ms |
| `ADD COLUMN x double precision DEFAULT random()` (volatile) | ACCESS EXCLUSIVE **suốt rewrite** | 29 ms | **2 100 ms** | **23 201 ms** |
| `ALTER COLUMN amount TYPE bigint` | ACCESS EXCLUSIVE **suốt rewrite** | 25 ms | **1 570 ms** | **20 319 ms** |
| `ADD CONSTRAINT CHECK (amount >= 0)` | ACCESS EXCLUSIVE suốt lần quét | 1.4 ms | 78 ms | 616 ms |
| `… CHECK … NOT VALID` | chớp nhoáng | 0.36 ms | 0.45 ms | 0.43 ms |
| `VALIDATE CONSTRAINT` sau đó | ShareUpdateExclusive (ghi vẫn chạy) | 0.97 ms | 67 ms | 658 ms |
| `ALTER COLUMN pad SET NOT NULL` | ACCESS EXCLUSIVE suốt lần quét | 1.5 ms | 110 ms | 956 ms |
| `CREATE INDEX (amount)` | ShareLock: chặn ghi | 7.0 ms | 295 ms | 3 178 ms |
| `CREATE INDEX CONCURRENTLY (amount)` | ShareUpdateExclusive | 8.0 ms | 518 ms | 5 143 ms |

## Giải thích
- **Hai nhóm rõ rệt:** (1) chỉ đổi catalog: thời gian ~1 ms ở mọi quy mô (O(1)) — gồm `ADD COLUMN` không default hoặc default **hằng** (Postgres 11+ lưu default trong catalog, dòng cũ đọc ra giá trị đó mà không viết lại); (2) phải chạm từng dòng: tuyến tính theo N (rewrite: 25 ms → 1.6 s → 20 s, ×~64 rồi ×~13 vì cache; quét kiểm tra: 1.5 → 110 → 956 ms).
- **Thời gian lệnh = thời gian giữ khóa, và `ACCESS EXCLUSIVE` chặn cả `SELECT`:** rewrite 10M dòng khóa bảng **23 giây**; kèm hàng đợi lock (P08) làm mọi truy vấn xếp sau cũng đứng. Ngoài ra `ROLLBACK` sau rewrite 10M còn tốn 1.3–1.5 s để bỏ file mới.
- **Chia đôi để tránh khóa lâu:** `ADD CONSTRAINT … NOT VALID` (0.4 ms) + `VALIDATE` (0.66 s nhưng ghi vẫn chạy) thay cho `ADD CONSTRAINT` trần (0.62 s chặn mọi thứ). Với bảng 10M, 0.6 s chưa đáng sợ; với hàm kiểm tra đắt hoặc bảng 1 tỉ dòng thì khác (ex07 mô phỏng bằng hàm chậm). Đổi kiểu `int → bigint` an toàn: thêm cột mới, backfill theo lô (ex08), đổi tên.
- **CONCURRENTLY chậm hơn 1.6–1.75×** (3.2 → 5.1 s ở 10M) nhưng không chặn ghi (ex04). Chọn khi bảng đang có ghi.
- **Chưa đo:** `shop_l`; khóa thực tế dưới tải ghi (ex04, ex07 đo bằng writer); thời gian khi bảng có nhiều index (rewrite phải dựng lại tất cả index: `ALTER TYPE` trên cột có index còn tốn hơn).
