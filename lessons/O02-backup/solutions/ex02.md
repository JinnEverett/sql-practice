# O02 · ex02 · Đọc nội dung bản dump trước khi restore

Trên cùng file `m.dump` của ex01 (`pg_dump -Fc shop_m`).

```bash
docker exec sql-practice-pg pg_restore -l /tmp/m.dump | head      # danh mục (TOC)
docker exec sql-practice-pg bash -c "pg_dump -U postgres -s shop_m | wc -c"          # schema-only: 13 223 byte
docker exec sql-practice-pg bash -c "pg_dump -U postgres -Fc -t users shop_m | wc -c" # chỉ bảng users: 3 081 924 byte
```
Số đo thật:
- Danh mục có **72 dòng** (extension, schema `bench`, 2 hàm `bench.*`, bảng `categories, events, order_items, orders, payments, products, users`, sequence, constraint, index…). Header ghi `Dumped from database version: 18.6`, `Compression: gzip`, `Format: CUSTOM`.
- Schema-only (`-s`) chỉ **13 KB**, dùng để dựng lại cấu trúc/so sánh phiên bản schema giữa các môi trường.
- Dump riêng bảng `users` (100 000 dòng) ≈ **3 MB**.

## Trả lời
1. `pg_restore -l` liệt kê `TABLE`, `TABLE DATA`, `INDEX`, `CONSTRAINT`… Thứ tự restore: schema + dữ liệu trước, **index/constraint sau** (nên restore chậm hơn dump: ex03). Có thể lưu danh mục vào file, bỏ bớt dòng rồi dùng `pg_restore -L file` để khôi phục có chọn lọc.
2. Phần `TABLE DATA` nằm riêng với `INDEX`/`FK CONSTRAINT`: dùng `--section=pre-data|data|post-data` để tách bước.
3. `-s` (schema-only) và `-a` (data-only) bổ sung nhau; dump `-t` một bảng **không** kèm bảng mà nó tham chiếu (FK) nên restore vào DB khác có thể lỗi thiếu bảng cha.
