# F09 · DDL & Constraints

Đọc khoảng 10 phút. Ví dụ chạy trên DB **`lab`** (schema `f09`, chạy `setup.sql` trước).

## Mục tiêu: sau buổi này bạn làm được
- Viết `CREATE TABLE` với kiểu dữ liệu đúng, khóa chính **identity**, `DEFAULT`, `NOT NULL`.
- Đặt luật nghiệp vụ vào database bằng **`CHECK`, `UNIQUE`, `FOREIGN KEY`**, biết chọn hành vi `ON DELETE`.
- Dùng **partial unique index**, **unique trên biểu thức** và **exclusion constraint** cho các luật mà `UNIQUE` thường không diễn đạt được.
- Sửa bảng đang có dữ liệu bằng `ALTER TABLE`, và biết lệnh nào phải **ghi lại cả bảng**.

---

## 1. Vì sao để database giữ luật?
Code ứng dụng có thể sai, có thể chạy song song, có thể bị bỏ qua (script tay, service khác). Constraint thì **luôn** được kiểm tra, kể cả khi 2 request chạy cùng lúc. Quy tắc: **luật nào diễn đạt được bằng constraint thì đặt vào constraint.**

## 2. `CREATE TABLE` và identity
```sql
CREATE TABLE f09.demo (
  id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,  -- tự sinh, cấm điền tay
  email      text NOT NULL UNIQUE,
  status     text NOT NULL DEFAULT 'new',
  created_at timestamptz NOT NULL DEFAULT now()
);
INSERT INTO f09.demo (email) VALUES ('a@x.vn') RETURNING id, status, created_at;
INSERT INTO f09.demo (id, email) VALUES (10, 'b@x.vn');
-- ERROR: cannot insert a non-DEFAULT value into column "id"   (SQLSTATE 428C9)
```
- `GENERATED ALWAYS AS IDENTITY`: cấm điền tay, muốn ép thì phải viết `OVERRIDING SYSTEM VALUE`. `GENERATED BY DEFAULT`: cho điền tay. Điền tay dễ làm lệch sequence: lần chèn tự động sau sinh trùng id đã điền và lỗi PK.
- `serial` là cách cũ. Nó tạo sequence rời, phải cấp quyền riêng và dễ lệch khi copy bảng. Code mới nên dùng identity.
- Khóa **surrogate** (`id` tự sinh) và khóa **tự nhiên** (`sku`, `email`) không loại trừ nhau. Thường dùng `id` làm PK và đặt `UNIQUE` cho khóa tự nhiên.

## 3. Năm loại ràng buộc
| Ràng buộc | Ý nghĩa | Lỗi |
|---|---|---|
| `NOT NULL` | bắt buộc có giá trị | `23502` |
| `UNIQUE` | không trùng, tự tạo unique index | `23505` |
| `PRIMARY KEY` | `UNIQUE` + `NOT NULL`, mỗi bảng một PK | `23505` / `23502` |
| `CHECK (biểu thức)` | biểu thức phải **không FALSE** | `23514` |
| `FOREIGN KEY … REFERENCES` | giá trị phải tồn tại ở bảng cha | `23503` (`23001` nếu `RESTRICT`) |

Ràng buộc nhiều cột viết ở **mức bảng**: `CHECK (ends_at > starts_at)`, `PRIMARY KEY (order_id, line_no)`.

## 4. ⚠️ NULL trong constraint
```sql
CREATE TEMP TABLE t (p int CHECK (p > 0), e text UNIQUE);
INSERT INTO t VALUES (NULL, NULL), (NULL, NULL);   -- cả hai dòng đều HỢP LỆ
```
- `CHECK` chỉ chặn khi biểu thức là **FALSE**. NULL không phải FALSE, nên dòng được cho qua. Muốn bắt buộc có giá trị thì thêm `NOT NULL`.
- `UNIQUE` coi các NULL là **khác nhau**, nên nhiều dòng NULL vẫn hợp lệ. Muốn chỉ cho phép một NULL thì dùng `UNIQUE NULLS NOT DISTINCT` (Postgres 15+).
- Có lúc đây lại đúng là điều ta muốn. Ví dụ "`ends_at` để trống = vô thời hạn": `CHECK (ends_at > starts_at)` tự cho NULL đi qua.
- "Đúng một trong hai cột có giá trị": `CHECK (num_nonnulls(a, b) = 1)`.

## 5. Khóa ngoại và `ON DELETE`
```sql
customer_id int NOT NULL REFERENCES customers (id) ON DELETE RESTRICT
```
| Hành vi | Khi xóa dòng cha |
|---|---|
| `NO ACTION` (mặc định) / `RESTRICT` | báo lỗi nếu còn dòng con |
| `CASCADE` | xóa luôn dòng con. Chỉ dùng khi con là **một phần** của cha (dòng hàng của đơn) |
| `SET NULL` / `SET DEFAULT` | giữ dòng con, xóa liên kết (nhân viên khi quản lý nghỉ) |

- ⚠️ **Postgres KHÔNG tự tạo index cho cột FK.** Khi xóa hoặc sửa khóa ở bảng cha, Postgres phải tìm các dòng con. Nếu không có index, nó quét cả bảng con mỗi lần. Thường nên tạo index cho cột FK, trừ khi cột đó đã là **cột đầu** của một index khác (ví dụ PK `(order_id, line_no)` đã phủ `order_id`).
- `CASCADE` trên dữ liệu quan trọng (khách → đơn) rất nguy hiểm: một lệnh `DELETE` xóa sạch lịch sử.

## 6. Index đặc biệt làm ràng buộc
```sql
-- Unique trên BIỂU THỨC: email không phân biệt hoa/thường, khoảng trắng
-- (chạy thẳng trên dữ liệu setup sẽ LỖI "could not create unique index" vì đang có email trùng: phải dọn trước, xem ex04)
CREATE UNIQUE INDEX ON f09.legacy_users (lower(trim(email)));
-- Partial unique: tối đa 1 địa chỉ mặc định mỗi khách (dòng is_default = false không bị giới hạn)
CREATE UNIQUE INDEX ON addresses (user_id) WHERE is_default;
```

## 7. Exclusion constraint: "không chồng nhau"
`UNIQUE` chỉ chặn được hai giá trị **bằng nhau**. Muốn chặn hai khoảng thời gian **giao nhau** thì dùng `EXCLUDE`:
```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;        -- cho phép dùng `=` trên cột int trong index gist
CREATE TABLE f09.demo_booking (
  room_id   int NOT NULL,
  starts_at timestamptz NOT NULL,
  ends_at   timestamptz NOT NULL,
  EXCLUDE USING gist (room_id WITH =, tstzrange(starts_at, ends_at) WITH &&)
);
```
- Hai dòng xung đột khi **mọi** cặp toán tử đều đúng: cùng phòng (`=`) **và** khoảng thời gian giao nhau (`&&`). Lỗi trả về là `23P01`.
- `tstzrange(a, b)` mặc định có cận `[)`: gồm điểm đầu, không gồm điểm cuối. Nhờ vậy 9–10h và 10–11h không bị coi là giao nhau.
- Có thể thêm `WHERE (…)` để constraint chỉ áp lên một phần dòng, giống partial index.

## 8. Generated column
```sql
line_total numeric(14,2) GENERATED ALWAYS AS (round(quantity * unit_price, 2)) STORED
```
Database tự tính giá trị, ứng dụng không ghi đè được (lỗi `428C9`). Biểu thức phải *immutable*: không dùng `now()`, không đọc bảng khác. Từ Postgres 18 có thêm `VIRTUAL`, tính lúc đọc và không chiếm chỗ trên đĩa.

## 9. `ALTER TABLE` trên bảng có dữ liệu
```sql
ALTER TABLE t ADD COLUMN c int DEFAULT 0;                    -- tức thì (default hằng số)
ALTER TABLE t ALTER COLUMN price TYPE numeric(12,2)
  USING regexp_replace(price, '[^0-9]', '', 'g')::numeric;   -- đổi kiểu + chuyển dữ liệu, GHI LẠI cả bảng
ALTER TABLE t ADD CONSTRAINT c_chk CHECK (c >= 0) NOT VALID; -- tức thì, chỉ kiểm tra dòng mới
ALTER TABLE t VALIDATE CONSTRAINT c_chk;                     -- quét dữ liệu cũ, lock nhẹ hơn
```
- Thêm ràng buộc khi dữ liệu cũ đang vi phạm thì lệnh lỗi. Phải dọn dữ liệu trước, rồi mới thêm ràng buộc.
- Hầu hết `ALTER TABLE` cần **ACCESS EXCLUSIVE** lock, chặn cả đọc lẫn ghi. Lệnh nào phải ghi lại cả bảng thì giữ lock lâu. Bonus của bài đo chuyện này.

## Bẫy hay gặp
1. `CHECK` không kèm `NOT NULL` → NULL lọt qua.
2. Regex trong `CHECK` thiếu `^…$` → chuỗi chỉ cần "chứa" mẫu là lọt qua.
3. `UNIQUE (user_id, is_default)` để diễn đạt "tối đa 1 mặc định" → chặn luôn địa chỉ thường thứ hai. Dùng partial unique index.
4. Quên index cho cột FK → `DELETE` ở bảng cha chậm dần theo kích thước bảng con.
5. Điền tay `id` vào cột identity `BY DEFAULT` → sequence lệch, lần chèn sau lỗi PK.

## Postgres-specific
- MySQL (InnoDB) **tự tạo** index cho FK. Postgres thì không.
- Trong Postgres, DDL chạy được trong transaction (`BEGIN; CREATE …; ROLLBACK;`). MySQL thì không. Vì vậy script chấm có thể thử DDL của bạn rồi hủy.
- Exclusion constraint, partial index, index trên biểu thức là các điểm mạnh riêng của Postgres.
