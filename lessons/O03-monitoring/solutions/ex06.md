# O03 · ex06 🔴 "Database chậm cả tuần: tìm top 5 query tệ nhất"

Tải giả lập: `docker exec -i sql-practice-pg psql -U postgres -d shop_m -X -q < lessons/O03-monitoring/shop-workload.sql` (≈ 28 s trên `shop_m`, Postgres 18.6; gồm sáu họ truy vấn, một số gọi cả nghìn lần).

```sql
SELECT calls, round(total_exec_time) AS total_ms, round(mean_exec_time::numeric, 2) AS mean_ms,
       shared_blks_hit + shared_blks_read AS blks, left(regexp_replace(query, '\s+', ' ', 'g'), 75) AS query
FROM pg_stat_statements WHERE query NOT ILIKE '%pg_stat_statements%'
ORDER BY total_exec_time DESC LIMIT 5;
```
Kết quả thật:
```
 calls | total_ms | mean_ms |  blks  | query
     3 |    12038 | 4012.80 | 135729 | SELECT count(*) FROM events WHERE properties->>$1 = $2
    20 |     4706 |  235.30 | 238580 | SELECT count(*) FROM orders WHERE user_id = $1
    10 |     2612 |  261.24 | 134710 | SELECT u.country, count(*) FROM orders o JOIN users u ON u.id = o.user_id GROUP BY 1
     5 |     1608 |  321.69 |  59645 | SELECT date_trunc($1, created_at), sum(total_amount) FROM orders GROUP BY 1
    50 |      586 |   11.72 |  19900 | SELECT id FROM products WHERE lower(name) LIKE $1
(2000 |      194 |    0.10 |   8003 | SELECT * FROM orders WHERE id = $1   ← gọi nhiều nhất nhưng chỉ đứng thứ 6)
```

## Chẩn đoán từng query (đã kiểm bằng `EXPLAIN (ANALYZE, BUFFERS)`)
1. **events `->>`**: mean 4 013 ms nhưng `min_exec_time` 209 ms, `max_exec_time` 11 608 ms. Lần đầu đọc **nguội** (`shared_blks_read` 134 037), hai lần sau ~0.2 s (chạy lại tay: 186 ms, Parallel Seq Scan 3.2M dòng). Bài học: **mean che giấu phân phối**; xem `min/max/stddev_exec_time` và `shared_blks_read`. Hướng xử lý: index biểu thức hoặc GIN (I07 ex10, P05); kiểm tra lại ở quy mô `l` vì index chưa chắc thắng.
2. **orders `WHERE user_id = ?`**: không có index trên `user_id` → Parallel Seq Scan 1M dòng mỗi lần (11 929 buffers, 27 ms khi nóng; lần nguội 3.9 s). Một index `orders(user_id)` đưa nó về vài chục µs (đo ở O01 ex07: 0.018 ms). Ứng viên số 1 vì **gọi thường xuyên**.
3. **join users × orders GROUP BY country**: quét cả hai bảng, 261 ms mỗi lần. Báo cáo, không nên chạy trên OLTP: chuyển sang materialized view hoặc replica (I09, O06).
4. **date_trunc GROUP BY**: quét cả `orders` mỗi lần (322 ms); cùng hướng: matview/bảng tổng hợp.
5. **`lower(name) LIKE 'a%'`**: Seq Scan 20 000 dòng, 7.5 ms/lần nhưng gọi 50 lần; nhỏ trong tổng thể. `lower(name)` cần index biểu thức (`text_pattern_ops`) mới dùng được cho `LIKE 'a%'` (P02, P05).

## Cách xếp hạng "tệ nhất"
Sắp theo `total_exec_time` (tài nguyên đã tốn), rồi xét `calls × lợi ích khi sửa`: truy vấn 2 (gọi 20 lần, sửa bằng một index) thường có lợi hơn truy vấn 1 (chỉ 3 lần, trong đó một lần nguội). Query `orders WHERE id = ?` gọi 2000 lần nhưng 0.1 ms/lần → không cần đụng. Luôn xem thêm `rows` và `shared_blks_*`, và sau khi sửa phải `pg_stat_statements_reset()` rồi đo lại.
