# O03 · ex05 · Log query chậm và auto_explain

Chạy trong một session superuser (đặt tham số ở mức session nên không đụng cấu hình server):
```sql
SET log_min_duration_statement = 200;           -- ms; -1 tắt, 0 ghi mọi câu lệnh
SELECT pg_sleep(0.05);                          -- 50 ms: không ghi
SELECT pg_sleep(0.3);                           -- 300 ms: ghi
LOAD 'auto_explain';
SET auto_explain.log_min_duration = 0;
SET auto_explain.log_analyze = on;
SET auto_explain.log_buffers = on;
SELECT count(*) FROM o03.big WHERE grp = 7;
```
Log (xem bằng `docker logs sql-practice-pg`; server ghi ra stderr, `logging_collector = off`), kết quả thật:
```
LOG:  duration: 300.603 ms  statement: SELECT pg_sleep(0.3);
LOG:  duration: 11.278 ms  plan:
	Query Text: SELECT count(*) FROM o03.big WHERE grp = 7;
	Finalize Aggregate  (cost=6565.59..6565.60 rows=1 width=8) (actual time=8.723..11.268 rows=1.00 loops=1)
	  Buffers: shared hit=4000
	  ->  Gather  ...  Workers Planned: 2  Workers Launched: 2
	        ->  Partial Aggregate ...
	              ->  Parallel Seq Scan on big  (actual time=0.012..5.686 rows=1000.00 loops=3)
	                    Filter: (grp = 7)
	                    Rows Removed by Filter: 99000
```
Câu `pg_sleep(0.05)` (< 200 ms) không xuất hiện; câu 300 ms xuất hiện dạng `duration … statement`; `auto_explain` (chạy ở ngưỡng 0) ghi **plan thật kèm số liệu thực thi** của câu truy vấn, giống `EXPLAIN (ANALYZE, BUFFERS)` mà không cần chạy lại bằng tay.

## Giải thích
- `log_min_duration_statement` biết **câu nào chậm**; `auto_explain` biết **vì sao chậm** (plan lúc chạy thật, kể cả khi plan khác với lúc bạn chạy tay do tham số/cache). Ngưỡng hợp lý trên production: vài trăm ms đến vài giây, kèm `auto_explain.sample_rate` nếu tải lớn.
- `log_analyze = on` làm đo thời gian từng node nên có chi phí: xem ex07 (−35% tps với ngưỡng 0). `log_analyze = off` chỉ ghi plan ước lượng, rẻ hơn.
- Cấu hình bền vững: `ALTER SYSTEM SET log_min_duration_statement = '500ms'` + `SELECT pg_reload_conf()`, và `session_preload_libraries = 'auto_explain'` cho cả database (cần nạp thư viện lúc kết nối). `log_line_prefix` nên có `%t [%p] %u@%d %a` để biết ai chạy.
- Đừng ghi `log_min_duration_statement = 0` lâu trên production: log phình rất nhanh và tốn CPU (ex07).
