# O03 · ex04 🔴 "Ứng dụng treo: ai đang chặn ai?"

Dựng tình huống (hai terminal, DB `lab`, sau khi chạy `setup.sql`):
```sql
-- Terminal 1 (A): giữ khóa dòng, chưa COMMIT
BEGIN; UPDATE o03.small SET v = v + 1 WHERE id = 1; SELECT pg_sleep(40);
-- Terminal 2 (B): bị chặn
UPDATE o03.small SET v = 0 WHERE id = 1;
```
## Truy vấn điều tra và kết quả thật (Postgres 18.6)
```sql
SELECT pid, state, wait_event_type, wait_event, pg_blocking_pids(pid) AS blocked_by,
       now() - xact_start AS xact_age, left(query, 60) AS query
FROM pg_stat_activity WHERE datname = 'lab' AND pid <> pg_backend_pid() ORDER BY xact_start;
```
```
 pid | state  | wait_event_type |  wait_event   | blocked_by |    xact_age     |                  query
 444 | active | Timeout         | PgSleep       | {}         | 00:00:04.03     | SELECT pg_sleep(40)
 451 | active | Lock            | transactionid | {444}      | 00:00:03.04     | UPDATE o03.small SET v = 0 WHERE id = 1
```
- Session 451 chờ `Lock/transactionid` (chờ transaction của 444 kết thúc), `pg_blocking_pids(451) = {444}`.
- Chuỗi chặn dạng bảng (nối chính `pg_stat_activity` với `unnest(pg_blocking_pids(pid))`):
```sql
SELECT blocked.pid AS blocked_pid, blocker.pid AS blocker_pid, left(blocked.query, 40) AS blocked_q,
       blocker.state AS blocker_state, now() - blocker.xact_start AS blocker_xact_age
FROM pg_stat_activity blocked
JOIN LATERAL unnest(pg_blocking_pids(blocked.pid)) b(pid) ON true
JOIN pg_stat_activity blocker ON blocker.pid = b.pid;
-- 451 | 444 | UPDATE o03.small SET v = 0 WHERE id = 1 | active | 00:00:04.30
```
- `pg_locks` cho thấy 451 có một khóa `transactionid ShareLock` với `granted = f` (đang chờ) và giữ khóa `tuple` ở `small`; 444 giữ `transactionid ExclusiveLock` và `RowExclusiveLock` trên `small`, `small_pkey`.

## Biến thể: "idle in transaction"
Ứng dụng mở transaction, `UPDATE` xong rồi quên `COMMIT`:
```
 pid |        state        |    idle_for     |    xact_age     |                  last_query
 636 | idle in transaction | 00:00:06.98     | 00:00:06.98     | UPDATE o03.small SET v = v + 1 WHERE id = 2;
```
Session này không chạy gì nhưng **giữ khóa và chặn VACUUM** (P07). Xử lý khẩn cấp: `SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE state = 'idle in transaction' AND now() - state_change > interval '5 seconds'` (đã chạy: kết thúc phiên đó, transaction rollback). Phòng ngừa: `idle_in_transaction_session_timeout`, `lock_timeout`, `statement_timeout` ở role của ứng dụng; sửa ứng dụng để luôn COMMIT/ROLLBACK.

## Quy trình đề xuất
1. `pg_stat_activity` (state, wait_event_type = 'Lock', `pg_blocking_pids`) → tìm kẻ chặn gốc (blocker không bị ai chặn).
2. Xem kẻ chặn đang làm gì: `active` (query dài) hay `idle in transaction` (quên commit).
3. `pg_cancel_backend(pid)` (hủy câu lệnh hiện tại) trước; `pg_terminate_backend(pid)` (cắt kết nối) nếu cần. Ghi lại nguyên nhân.
