# O04 · ex05 — Cấu hình PgBouncer (transaction mode)

## Dựng PgBouncer trong một container tạm
Dùng lại image `postgres:18` (đã có sẵn), cài `pgbouncer` bằng apt, đặt cùng mạng Docker với `sql-practice-pg`:
```bash
NET=$(docker inspect sql-practice-pg --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}}{{end}}')
docker run -d --name o04-pgb --network $NET --entrypoint sleep postgres:18 3600
docker exec o04-pgb bash -c "apt-get update -qq && apt-get install -y -qq pgbouncer"      # PgBouncer 1.26.0
docker exec o04-pgb mkdir -p /etc/pgbouncer /var/log/pgbouncer
docker cp lessons/O04-connections/pgbouncer/pgbouncer.ini o04-pgb:/etc/pgbouncer/
docker cp lessons/O04-connections/pgbouncer/userlist.txt  o04-pgb:/etc/pgbouncer/
docker exec o04-pgb bash -c "chown -R postgres /etc/pgbouncer /var/log/pgbouncer; su postgres -c 'pgbouncer -d /etc/pgbouncer/pgbouncer.ini'"
docker exec -e PGPASSWORD=postgres o04-pgb psql -h 127.0.0.1 -p 6432 -U postgres -d o04_bench -c "select 1"
# dọn: docker rm -f o04-pgb
```
(Lỗi gặp khi dựng: `FATAL daemon needs pidfile configured` — chạy `-d` thì bắt buộc có `pidfile`. `userlist.txt` chứa mật khẩu `postgres` của DB lab, chỉ dùng cho bài này.)

## Tham số đã chọn (`pgbouncer/pgbouncer.ini`) và lý do
| Tham số | Giá trị | Vì sao |
|---|---|---|
| `pool_mode` | `transaction` | trả kết nối server khi COMMIT/ROLLBACK; 320 client không cần 320 kết nối server |
| `max_client_conn` | 500 | ≥ 8 × 40 = 320 + dư địa; mỗi client chỉ tốn vài KB |
| `pool_size` (trong `[databases]`) | 10 | số kết nối **server**; vài lần số core là đủ (O04 mục 3), và còn xa mức 97 |
| `default_pool_size` | 10 | mặc định cho DB khác |
| `reserve_pool_size` / `reserve_pool_timeout` | 2 / 3 s | kết nối dự phòng khi client chờ quá 3 s |
| `query_wait_timeout` | 30 s | client chờ pool quá 30 s thì báo lỗi, thay vì treo mãi |
| `server_idle_timeout` | 600 s | trả bớt kết nối server nhàn rỗi |
| `auth_type` | `scram-sha-256` + `auth_file` | khớp cách server xác thực |

## Kết quả đo
`pgbench -S -c300 -j4 -T8`:

| | Kết quả |
|---|---|
| **Trực tiếp** vào server (`max_connections = 100`) | `FATAL: sorry, too many clients already` |
| **Qua PgBouncer** | **8 580 – 9 358 tps** (2 lần đo), 0 giao dịch lỗi, trễ trung bình 32 ms |

`SHOW POOLS` giữa lúc chạy:
```
 database  |   user   | cl_active | cl_waiting | sv_active | sv_idle | maxwait_us | pool_mode
 o04_bench | postgres |        24 |        276 |        10 |       0 |      27603 | transaction
```
- 300 client: 24 đang chạy, **276 xếp hàng** ở PgBouncer; chỉ **10** kết nối server hoạt động. Khi chạy, `pg_stat_activity` thấy 13 backend trên `o04_bench` (10 của PgBouncer + vài session của chính phép đo).
- Chờ lâu nhất 27,6 ms: hàng đợi ở pooler rẻ hơn hàng đợi bên trong server.

## Cái giá (đã đo)
| 4 client bền, `-S` | tps |
|---|---|
| trực tiếp | 11 371 |
| qua PgBouncer | 7 900 (**−30%**) |

PgBouncer thêm một chặng và là process đơn luồng. Chỉ đáng dùng khi có nhiều client hơn kết nối server cần, hoặc khi client hay mở/đóng kết nối (`-C`: 129 → 236 tps).
